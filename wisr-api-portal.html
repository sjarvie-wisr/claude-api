Wisr External API

Enable your customers to request rate estimates and submit loan applications directly through your platform via the Wisr REST API. JSON over HTTPS, standard HTTP verbs and response codes.

API Flow — End to End

1
POST Rate Estimate
Get wisrApplicationId
2
Poll GET Status
Wait ~7s, poll every 0.5s
3
PUT Draft App
Save full application
4
POST Submit
Submit for assessment
5
Poll GET Status
Track decision

⚡ Quickstart Guide

Make your first successful API call in 3 steps.

1

Get your credentials

You need an API key, partner-company-id, and optionally a partner-id (required for broker networks). Email apisupport@wisr.com.au to request access.

Read Auth Guide →
2

Configure your first request

Set the base URL to the sandbox and add your credentials as headers. Then POST to /apply/v3/application/rateEstimate

3

Send the test request

Use the sample body below. A 202 Accepted with a wisrApplicationId means you're connected!

🔑 Authentication

All API calls require three header values. Add them to every request.

Header (case-sensitive)RequiredDescription
subscription-keyRequiredYour unique API key. Keep secret — never commit to Git or expose client-side.
partner-company-idRequiredIdentifies the firm submitting on behalf of a customer.
partner-idConditionalIdentifies the individual broker. Only required when submitting on behalf of a specific broker.
🏢
Broker Networks: You will always need to include a partner-id in addition to the partner-company-id. Each broker in your network has their own partner-id.
🔗
Referrers: You do not need to include a partner-id. Your partner-company-id is configured for referral-type submissions.

Hierarchy

One API Key → many partner-company-ids → many partner-ids. All three must be validly related — mismatches return 400 Bad Request.

Request credentials: apisupport@wisr.com.au

POST Submit Rate Estimate

The starting point for all new loans. Submit applicant data and receive a wisrApplicationId to poll for the outcome.

POST /apply/v{version}/application/rateEstimate
PerformanceTarget
Average response< 500ms (acknowledgement only — not the rate estimate outcome)
95th percentile< 2000ms

Key Parameters

FieldTypeRequiredNotes
loanAmountnumberRequiredAmount to borrow
loanPurposestringRequirede.g. "holiday", "car", "consolidation"
requestSecuredRatebooleanOptionalDefaults to true when loanPurpose is "car"
rateDiscountnumberBroker onlyUp to 2.00% for eligible brokers on secured loans
brokerFeenumberBroker onlyCustom fee; cannot exceed the default fee
applicantsarrayRequiredOne applicant only at this stage
declarationsobjectRequiredAll four consents must be true
🏢
Broker Networks: You can set a custom brokerFee and rateDiscount (secured loans only). Rate discounts reduce commission proportionally. The loan will appear in the Wisr Broker Portal for follow-up.
🔗
Referrers: After polling the status, you'll receive an applyUrl to direct the customer to wisr.com.au to complete their application. No brokerFee or rateDiscount applies.

Response

Success: 202 Accepted — store the wisrApplicationId immediately, you'll need it for all subsequent calls.

Response
{
  "wisrApplicationId": "1d5f30ee-d16b-427b-8749-d491de859064"
}

GET Rate Estimate Status

Poll this endpoint to get the outcome of a rate estimate. Wait 5 seconds after the initial POST, then poll every 500ms until a definitive status is returned.

GET /apply/v{version}/application/{wisrApplicationId}/rateEstimate
PerformanceAverage95th Percentile
Total processing time< 7,000ms< 11,000ms
Bureau response time~6,100ms~10,000ms

Status Outcomes

RateEstimateSuccessful
Rate estimate generated. allowApplication: true — you can proceed to submit an application.
RateEstimatePending
Still processing — keep polling every 500ms.
RateEstimateReduced
Customer eligible for a lower amount than requested. The estimate reflects the maximum eligible amount.
RateEstimateDeclined
Does not meet credit policy. Stop polling.
RateEstimateNoRecord
Equifax file not found. Try with additional identity documents or previous addresses.
RateEstimateExpired
Estimate is older than 30 days. Request a new one.
RateEstimateAccountSuspended
Broker account suspended. Contact BDM.
🔗
Referrers: A successful response includes an applyUrl. Direct your customer to this URL to complete their application on wisr.com.au — no PUT/POST application calls needed from your side.

PUT Save Application Draft

Save all full application data following a successful rate estimate where allowApplication: true. You can PUT multiple times progressively — the last PUT overwrites the full dataset.

PUT /apply/v{version}/application/{wisrApplicationId}

⚠️ Do not omit fields from the rate estimate — the PUT replaces the entire dataset. Any omitted field reverts to blank/default.

New FieldTypeRequiredNotes
LoanRequirementsAndObjectivesstringRequiredResponsible lending requirement
offerIdstringRequiredThe indicative quote ID (3, 5 or 7yr term) from the rate estimate
financialDetailsobjectRequiredExpenses, liabilities, assets
SignificantPlannedChangesobjectRequiredAny anticipated changes impacting repayment capacity
directDebitBankAccountobjectOptionalBank account for loan repayments
useESignatureContractbooleanOptionalDefaults to true (eSign). Set false for PDF contracts sent to broker.
🏢
Broker Networks: Use loanAdditionalNotes to pass notes to the Wisr assessor. Set useESignatureContract: false if you prefer PDF contracts sent directly to the broker.

POST Submit Application

Submit the application for credit assessment after a successful PUT. Returns 202 Accepted — then poll GET application status for the outcome.

POST /apply/v{version}/application/{wisrApplicationId}/submit

The request body should be empty. The wisrApplicationId in the URL identifies the application. Use the same partner-company-id and partner-id headers as used on the original rate estimate.

GET Application Status

Poll for the credit decision on a submitted application.

GET /apply/v{version}/application/{wisrApplicationId}/status
Approved
Loan approved and contract sent (eSign or PDF per your setting).
PreSubmitServicingFailed
(v3+) Customer does not meet servicing requirements prior to submission.
Pending / InReview
Assessment in progress — continue polling.
Declined
Application did not meet credit policy.

GET Terms & Conditions

Always fetch T&C content from this endpoint to ensure you're presenting the latest version to customers — never hardcode the text.

GET /apply/v{version}/terms

The endpoint returns content for all four declaration fields required on both rate estimate and application draft requests: meetsEligibility, privacyConsent, accessSeekerCreditReportConsent, and electronicCommunicationConsent.

⚠️ Error Handling

The API uses standard HTTP status codes. All error responses include a message to help debug the issue.

CodeMeaningCommon Cause
400 Bad RequestValidation errorMissing/invalid partner IDs, malformed request body
401 UnauthorizedAuth failedInvalid or missing subscription-key
202 AcceptedSuccessRequest received and valid
429 Too Many RequestsRate limitedPolling too frequently — back off and retry
5xx Server ErrorWisr-side errorContact apisupport@wisr.com.au

All requests must be made over HTTPS. HTTP calls will fail. Contact apisupport@wisr.com.au for persistent issues.

✅ Validation Guide

Key validation rules to be aware of when constructing requests.

FieldRule
doBFormat: DD/MM/YYYY
startDate / endDateFormat: MM/YYYY
addressesPrevious address required if current address < 36 months. Time calculated inclusively.
employmentsPrevious employment required if current employment < 6 months.
driverLicence.cardNumberRequired for all Australian states (mandatory since v2, Sept 2022)
investmentPropertyRequired on all rate estimate requests (mandatory since v3, June 2025)
rateDiscountMax 2.00% for eligible brokers on secured loans only
securedAssetDetails.yearOfManufactureAssets 13+ years old at loan start cannot be secured — defaults to unsecured
loanPurpose: "consolidation"Must include ≥1 creditCard or personalLoan with isForConsolidation: true
saleType: "refinance"Must include exactly 1 personalLoan with isForConsolidation: true
